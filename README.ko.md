# Dotdew Valley

[English](README.md) | 한국어

Dot Pad를 사용하는 농장·생활 시뮬레이션 게임. 집, 농장, 마을, 광산에서 농사·요리·채굴·거래·연구를 진행한다. Stardew Valley의 생활 활동을 참고했으며, 각 활동은 60×40 도트 화면 안에서 이루어진다.

마우스와 키보드로 브라우저에서 플레이하거나 USB 패드와 외부 손 추적 장치를 연결할 수 있다. Visual Companion은 게임 상태를 이미지로 보여주는 별도 창이다.

## 기획

시각장애인이 촉각과 소리로 공간을 파악하고 직접 활동을 수행하는 게임을 목표로 한다. 점자 문자를 읽지 않아도 도형과 음성으로 조작할 수 있도록 구성했다.

| 구분 | 용도 |
|---|---|
| 촉각 | 위치, 형태, 배치, 활동 경로와 진행 상태 |
| 음성·효과음 | 이름, 수량, 상태, 행동 결과 |
| 시각화 | 약시 사용자와 동행자를 위한 이미지, 수량, 선택 표시 |
| 버튼 | 이동, 메뉴, 저장·로드, 선택 |
| 포인터·손 제스처 | 선택, 쓸기, 경로 따라가기, 타격 |

탐색과 이동에는 시간이 들지 않는다. 손을 올려 정보를 읽는 동작과 누르기 입력을 구분해 탐색 중에 활동이 실행되지 않도록 한다.

농사·요리·채굴·거래·연구·낚시와 NPC 1명의 기초 대화는 구현되어 있다. 목축·음악 활동·퀘스트·제작은 개발 예정이다. 아래 조작표는 초기 제안서의 키 배치가 아닌 현재 구현 기준이다.

## 실행

처음에는 Python 3.11 이상을 설치하고 Mac은 **setup-mac.command**, Windows는 **setup-windows.bat**를 연다. 프로젝트 안에 실행 환경을 만들고 패키지·블루투스 SDK·두 음성을 준비한다. 최초 설치에는 인터넷이 필요하다. 이후에는 **start-mac.command** 또는 **game.bat**만 연다. 실행 준비 확인, 서버 연결 대기와 시연 음성 준비 후 게임을 열며, 같은 포트의 게임이 이미 켜져 있으면 재시작 없이 사용한다. [설치와 전달 안내](docs/audio/SETUP.md)를 참고한다.

직접 설치하려면 프로젝트 루트에서 Python 가상환경을 준비하고 의존성을 설치한다.

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# macOS / Linux
source venv/bin/activate

python -m pip install -r requirements.txt
python tools/prepare_pad.py
python tools/prepare_speech.py --download
python launch_game.py --prepare-demo
```

Mac 실행 파일과 직접 실행 명령의 기본 주소는 `http://127.0.0.1:8000`이다. Windows `game.bat`는 기존 포트를 유지해 `http://127.0.0.1:8003`을 사용한다. 실제 주소는 실행창의 안내를 따른다. HTML을 파일 탐색기에서 직접 열지 말고 서버를 통해 실행한다.

1. 게임 페이지를 열고 클릭 또는 키 입력으로 음성을 활성화한다.
2. 마우스·키보드로 먼저 플레이하거나 USB 패드와 손 추적 서버를 연결한다.
3. **Open visual display**를 눌러 별도 시각화 창을 연다. 팝업이 차단되면 해당 사이트의 팝업을 허용한다.
4. 시각화 창을 사용할 때는 원래 게임 페이지도 열어 둔다.

설정 파일을 수정하면 서버를 재시작한다. 웹 파일을 교체한 뒤에는 Ctrl+F5로 새로고침하고 시각화 창도 다시 연다.

새로 설치한다면 Python 3.12 64비트를 권장한다. 실행 파일은 `.venv/`와 `venv/`를 인식한다. 두 환경 모두 설정을 UTF-8로 읽으며, 손상된 음성 파일은 설치 시 다시 받는다. 활성화한 환경에서 `python tools/check_setup.py --synthesize`로 파일·패키지·두 목소리를 점검할 수 있다. Windows와 Mac의 자동 설치 검사 결과는 GitHub Actions의 **Audio setup**에서 확인한다.

## 영어 음성과 Rowan 대화

10월 18일에는 서버의 오래된 음성 취소·우선순위, 최근 행동에 대한 Rowan의 일회성 반응, 농사·광산 목표 방향음을 추가했다. **Target cues on/off**로 새 목표음을 비교할 수 있고 낚시 탐색음은 유지한다. 반응은 실제 최근 결과를 기억하고 저장에도 포함되며, 기존 저장에서는 과거 최초 성취를 알 수 없으므로 일반 반응을 쓴다. [변경과 검증 결과](docs/audio/GAMEPLAY_UPDATE.md)를 참고한다.

음성은 Python 서버의 Piper와 고정 영어 모델로 생성한다. 브라우저나 운영체제의 목소리를 선택하지 않는다. 위의 음성 준비 명령은 모델 두 개를 `models/piper/`에 내려받고 샘플을 만든다. 모델과 생성 음원 `.cache/speech/`는 Git에서 제외한다. 현재 구현은 별도 음성 서비스 계정이나 API 키가 필요 없다. 새 문장은 처음 요청할 때 생성하고 이후 저장된 WAV를 재사용하므로, 첫 모델 로드와 새 문장은 저장된 문장보다 오래 걸릴 수 있다.

- **Test guide**는 버튼 안내를, **Test Rowan**은 상점주인 목소리를 재생한다.
- **Replay**는 대화 중에는 현재 NPC 대사를, 다른 화면에서는 최근 안내를 다시 읽는다. **Stop speech**는 현재 대사를 건너뛴다. **Speech on/off**, **Speech rate**는 효과음과 별도로 동작한다.
- **Speech volume**은 기본 85%이며 Rowan을 포함한 음성만 조절한다. **Sound volume**은 기존 게임 사운드를 조절한다. 대사 중 음량을 바꿔도 문장을 다시 시작하거나 재생성하지 않는다. 새로고침하면 음성 음량은 85%로 돌아온다.
- **상점 → Ask Rowan for advice**를 선택하면 **Farming**, **Fishing**, **Open shop**, **Goodbye**를 고를 수 있다. 농사 상태와 낚싯대 보유 여부에 맞춰 조언하며, 대화와 다시 듣기는 시간이나 재화를 쓰지 않는다. 마을 Rowan의 수프·씨앗·채소 제출 튜토리얼은 팀 코드대로 유지한다.
- 음성이 나오는 동안 배경음악을 평소 음량의 25%로 줄였다가 복구한다. 탐색 안내는 행동 결과나 대사가 끝난 뒤 재생한다. 낚시의 기존 HRTF 방향 계산과 TTS 중 탐색음 유지 설정은 보존한다.
- 게임 창을 떠나면 음성과 게임 소리를 멈추고 늦은 응답의 소리도 차단한다. 돌아오면 현재 화면의 배경음과 낚시 탐색음만 복구하며 음소거 설정은 유지한다. 이전 대사와 단발 효과음은 자동 재생하지 않는다. 늦게 도착한 문장은 자막과 **Replay**로 확인할 수 있다.
- 장면을 이동하면 이전 작업·목표·거래 소리와 늦은 채굴 획득 안내를 취소한다. 수면 녹음은 기존처럼 다음 날까지 이어진다. 음원 로딩에 실패하면 1초 뒤 이후 행동이나 상태 갱신에서 다시 시도하며, 지나간 효과음을 뒤늦게 재생하지 않는다.

목소리와 대표 문장은 `speech_config.json`, NPC 대사는 `npc_config.json`에서 관리한다. `python tools/prepare_speech.py`는 `output/audio/`의 비교 음원을, `python tools/speech_inventory.py`는 코드 내 문장 목록을 갱신한다. [사운드 목록과 모델 출처](docs/audio/SOUND_MAP.md), [팀 전달 안내](docs/audio/TEAM_HANDOFF.md)을 참고한다. 프로토타입 모델의 데이터셋 라이선스는 연결된 모델 카드에 기록된 CC BY NC SA 4.0이며 Piper는 GPL 3.0 이상이다.

시연 전에는 게임 서버를 실행한 상태에서 다른 터미널에 `python tools/prepare_demo.py`를 실행한다. 고정 안내, Rowan 튜토리얼·조언 대사와 대표 행동·대상·최근 반응 안내를 음성 API로 미리 준비하며 게임 진행은 바꾸지 않는다. 현재 기준 속도 1.0의 203문장이다. 다른 속도, 바뀌는 수량과 저장 시각 안내는 처음 생성할 수 있다. 결과는 `output/audio/demo-ready.json`에 저장한다. [시연 준비와 검증](docs/audio/DEMO_READY.md)을 참고한다.

이번 변경의 소프트웨어 검증은 `python -m unittest test_team_audio test_speech_queue test_speech_api test_gameplay_audio test_speech test_fishing test_sound_events test_audio_flow test_demo_speech test_startup -v`, `node --test test_speech.cjs test_guidance.cjs test_fishing_audio.cjs test_effects.cjs test_audio_integration.cjs test_hardware.mjs`로 실행한다. 총 147개 검사다. `python tools/audio_flow.py`는 임시 진행에서 농사·요리·NPC와 거래·채굴·낚시·저장과 로드를 기록한다. 별도 브라우저 검증은 `python tools/audio_integration_lab.py` 실행 후 `http://127.0.0.1:8001/`에 접속한다. 임시 물 주기 장면에서 시작하며 실제 사용자의 게임 진행은 사용하지 않는다. 범위와 테스트 조건은 [통합 검증 결과](docs/audio/INTEGRATION_REPORT.md)에 기록했다.

사용자는 첫 음성과 방향감·효과음 균형을 긍정적으로 평가하고 음성을 조금 낮춰 달라고 했다. 기본 음성 85%는 이 의견을 반영한 값이다. 세부 방향별 청취, 발음, 다른 컴퓨터와 실물 Dot Pad는 [청취 확인 순서](docs/audio/LISTENING_CHECK.md)에 따라 추가로 확인한다.

## 조작 가이드

| 입력 | 기능 |
|---|---|
| 포인터 올리기 | 오브젝트 이름과 상태 안내 |
| 클릭 | 선택, 시설 이용, 광산 타격 |
| 누른 채 이동 | 물·비료 뿌리기, 수확, 요리 경로 따라가기 |
| F1 | 미니맵 열기. 같은 메뉴에서 다시 누르면 현재 지역으로 복귀 |
| F2 | 인벤토리 열기. 같은 메뉴에서 다시 누르면 현재 지역으로 복귀 |
| F3 짧게 누르기 | 저장 목록 열기·닫기 |
| F3 길게 누르기 | 약 0.8초 동안 누르면 새 슬롯에 저장. `Game saved.` 안내 후에도 현재 화면 유지 |
| F4 | 포인터 위치 선택 (현재 사용자 평가용 매핑) |
| 좌우 화살표 키 / 패드 좌우 버튼 | 장소 이동 또는 현재 페이지에 지정된 뒤로가기·페이지 이동 |
| W / A / S / D | 게임 캔버스에 포커스가 있을 때 포인터 이동 |
| Shift + W / A / S / D | 포인터를 더 큰 간격으로 이동 |
| Enter | 포인터 위치 선택 |
| Space | 누르기·떼기 상태 전환 |

장소 이동은 왼쪽부터 **농장 ↔ 집 ↔ 마을 ↔ 광산** 순서다. 이동하면 도착 장소 이름을 음성으로 안내한다. 이동 경로가 없는 방향은 이동할 수 없다고 안내한다.

미니맵·인벤토리·로드 창에서는 좌우 어느 버튼을 눌러도 현재 지역으로 복귀한다. 상점 구매·판매의 뒤로가기는 판매·구매 선택 화면으로 연결된다. 상점의 페이지 이동 명령은 별도로 유지되며, 인벤토리 목록의 페이지 전환은 화면에 제공되는 이전·다음 항목을 이용한다.

손 추적은 외부 장치가 제공하는 좌표와 누름 상태를 게임 입력으로 변환한다. 좌표만 보내는 서버를 사용하는 경우 누르기 버튼이나 Space를 함께 사용한다. Dot Pad 자체가 터치 좌표를 감지하는 구조는 아니다. 새 행동 안내는 이전 안내를 중단하며, 탐색 안내는 행동 결과와 대사가 끝난 뒤 재생한다. 현재 안내 언어는 영어다.

## 장소와 게임 흐름

| 장소 | 활동 |
|---|---|
| 집 | 침대에서 수면, 연구, 주방에서 요리 |
| 농장 | 밭 선택, 씨앗 심기, 물·비료 주기, 성장 확인, 수확 |
| 마을 | 상점에서 구매·판매, 집과 광산으로 이동 |
| 광산 | 곡괭이로 돌을 부수고 광물 획득 |

농사로 얻은 작물은 판매하거나 요리 재료로 사용한다. 광물은 연구에 사용하거나 상점에서 거래한다. 연구로 밭을 늘리고 씨앗 회수와 광물 획득을 개선한다. 음식은 인벤토리에서 먹어 효과를 적용한다.

### 시간과 수면

시간은 실제 경과 시간이 아니라 활동 완료에 따라 소비되는 게임 시간이다. 현재 설정에서 하루는 20틱이며, 이동은 0틱, 심기·물·비료는 2틱, 수확·연구·요리는 3틱이다. 채굴은 타격마다가 아니라 돌을 완전히 부술 때 2틱을 사용한다.

활동 시간이 소진되면 집으로 돌아간다. 수면 시 도트 패널이 잠시 꺼지고 배경음악도 멈춘다. 수면 효과음은 한 번 재생되며 다음 날로 넘어가도 끝까지 이어진다. 실제 패드는 하단 도트 시간 패널을, 시각화는 사용한 시간에 따라 채워지는 얇은 주황색 막대를 사용한다.

### 농사

농장 화면의 밭을 선택하면 상세 관리 화면이 열린다. 빈 밭에는 씨앗을 심고, 작물이 있으면 성장·물·비료 상태를 확인한다. 농장에서는 밭 내부가 아래부터 채워지는 방식으로 성장을 표시하며, 상세 화면에서는 성장 상태와 관리 버튼을 제공한다.

물과 비료는 누른 상태로 목표를 지나가는 활동이다. 완료 기준은 `care_minigame.success_ratio`를 따르며, 기준에 못 미치면 남은 목표를 이어서 진행할 수 있다. 물을 준 작물은 수면 후 성장하고, 비료는 사용 즉시 성장일을 앞당긴다.

수확은 모든 목표를 통과해야 완료된다. 수확량은 작물의 기본 수량과 음식 효과로 계산하며, 미니게임 점수에 따른 수확량 배율은 사용하지 않는다. 씨앗 회수는 작물 기본 확률 또는 연구 단계에 따라 판정한다.

### 요리와 음식

레시피를 고른 뒤 필요한 재료를 모두 선택하면 조리가 자동으로 시작된다. 자르기 경로와 두 번째 경로를 순서대로 완료해야 음식이 만들어지고 재료와 시간이 소비된다. 시간제한은 없으며, 진행이 끊기면 재개할 지점을 표시한다. 지나간 경로는 설정한 지연 후 사라진다.

| 음식 | 재료 | 효과 | 지속시간 |
|---|---|---|---|
| Tomato carrot stew | 토마토·당근 | Harvest boost — 수확량 증가 | 6시간 |
| Potato tomato soup | 감자·토마토 | Pickaxe protection — 곡괭이 보호 | 10시간 |
| Vegetable fritters | 감자·당근 | Time saving — 시간 소모 감소 | 10시간 |

지속시간은 실제 시간이 아닌 게임 시간 기준이다. 야채 튀김의 두 번째 조리 경로는 8개 꽃잎 형태다. 음식은 인벤토리에서 사용하며 한 번에 하나의 효과가 적용된다. 다른 음식을 먹으면 효과가 교체되고, 지속시간은 소비한 게임 시간에 따라 줄어든다. 플레이 안내에는 세부 배율 대신 효과 이름과 지속시간을 표시한다.

### 상점과 인벤토리

상점은 씨앗·비료·곡괭이·일부 광물을 판매하고, 플레이어의 작물·음식·광물을 매입한다. 곡괭이는 한 개만 보유할 수 있으며 파괴되면 다시 구매한다.

인벤토리는 수량이 0인 항목을 숨기고 최대 12개씩 표시한다. 촉각 화면은 음식의 타원, 골드의 마름모, 일반 아이템의 사각형과 내부 도형으로 종류를 구분한다. 시각화는 모든 아이템을 사각형 카드에 넣고 테두리 색으로 구분하며, 이미지 아래에 이름·보유량·가격을 표시한다.

### 광산과 연구

광산에는 하루 최대 7개의 돌이 간격을 두고 배치된다. 기본적으로 세 번 타격하면 부서지며, 손상에 따라 내부 도트 밀도가 정해진 패턴으로 감소한다. 외곽은 유지하여 돌의 위치와 크기를 계속 읽을 수 있다.

돌·구리·철·다이아몬드를 획득할 수 있고 연구에 따라 보너스 수량이 나올 수 있다. 곡괭이 파괴 확률은 내부에서 관리하며 플레이 중 내구도 수치를 공개하지 않는다. 아이템이 파괴되는 타격에서는 일반 타격음 대신 공통 파괴음을 재생한다.

| 연구 | 재료 | 효과 |
|---|---|---|
| Seed recovery | 골드·구리 | 씨앗 회수 확률 개선 |
| Farm expansion | 골드·돌 | 기본 2개에서 최대 6개까지 밭 확장 |
| Mineral luck | 골드·철 | 광물 획득 확률과 보너스 획득 개선 |

연구 화면은 한 행에 3개씩 표시한다. 수확량 연구는 사용하지 않는다.

## 프로그램 구성

서버가 게임 상태와 판정을 관리하고, 브라우저가 입력을 전달한다. 마우스·키보드·하드웨어 입력은 이동·누름·드래그·떼기의 공통 이벤트로 처리한다. 응답에는 도트 화면, 공개 게임 상태, 음성 안내와 소리 이벤트가 포함된다.

### Visual Companion

시각화는 `web/spectator/`에서 관리하는 **별도의 읽기 전용 연동 창**이다. 게임 페이지에서 상태를 받아 장소, 선택, 미니게임 진행, 시간대와 수면을 표시한다. 이 창의 클릭이 게임 상태를 바꾸지는 않는다.

| 파일 | 역할 |
|---|---|
| `standalone.html` | 별도 시각화 창의 진입 페이지 |
| `viewer.js` | 화면·카드·오브젝트·진행 효과를 그리는 원본 코드 |
| `model.mjs` | 게임 상태와 시각화 배치·표현 사이의 변환 |
| `viewer.css` | 카드, 수량, 색상, 선택 강조, 시간 막대 스타일 |
| `display.js` | 실제 페이지에서 불러오는 실행용 묶음 |
| `build_display.py` | 원본 코드에서 실행용 `display.js` 생성 |
| `visual-assets.json` | 배경·시설·아이템 이미지 및 스프라이트 영역 등록 |
| `scene-objects.json` | 장소별 시설 위치·크기·표시 순서 |
| `assets/` | `scenes.png`, `scenes2.png`, `facilities.png`, `items.png`, `extras.png` 등 이미지 |

농장의 각 밭과 광산의 각 돌은 실제 게임 오브젝트와 연결된다. 농장은 개별 밭에 울타리를 두며, 상점은 왼쪽 목록과 오른쪽 상인·매대로 구성한다. 인벤토리와 상점은 한 페이지의 항목을 스크롤 없이 표시한다.

이미지 관리는 배경·시설·오브젝트 등록을 분리해 기존 이미지를 재사용한다. 새 활동의 화면이 아직 준비되지 않았으면 도트 화면을 표시하고, 등록되지 않은 아이템은 프레임과 이름으로 표시한다. 원본 코드를 수정한 경우 `display.js`도 다시 생성해야 실제 실행에 반영된다.

## 저장과 로드

F3을 길게 누르면 누르는 도중 저장이 실행된다. 저장 후 키를 떼어도 로드 화면이 추가로 열리지 않는다. F3을 짧게 누르면 저장 목록에서 슬롯을 고를 수 있다.

저장은 `saves/`의 JSON 파일 단위로 관리하며 최근 12개를 유지한다. 아이템·골드·날짜·밭 상태·연구·음식 효과·NPC 방문 등 게임 진행을 복원한다. 이전 저장에는 빈 NPC 상태를 추가한다. 저장 파일은 버전 관리 대상에서 제외한다. 서버 메모리의 진행은 재시작 시 초기화되므로 이어서 플레이하려면 저장 후 로드해야 한다. USB 연결, 카메라 보정, 음성 제어 설정은 게임 진행 저장과 별개다.

## 오디오

| 음원 | 상황 |
|---|---|
| `background-basic`, `background-minigame`, `background-shop` | 기본·미니게임·상점 배경음악 |
| `water`, `soil`, `crop` | 물·비료·수확 작업 |
| `cut`, `cook` | 자르기·젓기 |
| `correct` | 목표 통과와 일반 획득 피드백 |
| `step`, `door`, `coin` | 이동·상점 입장·거래 및 유료 연구 |
| `sleep` | 수면 시작 |
| `pickaxe`, `break`, `shine`, `destroy` | 타격·돌 파괴·다이아몬드 획득·아이템 파괴 |

음원은 `web/audio/`의 같은 이름 MP3를 사용한다. 작업음과 성공음은 별도 채널이므로 성공음이 작업음을 끊지 않는다. 같은 배경음악 그룹 안에서는 음악을 다시 시작하지 않는다. 영어 음성은 서버가 생성한 WAV를 재생하며, 효과음 음량 설정과 음성 설정은 별개다. TTS 중 배경음악 배율은 `interaction.audio.bgm_during_tts`로 조정하며 기본값은 0.25다.

작업 녹음과 짧은 결과음을 `GameAudio`로 통합했다. 목표 통과·전체 완료·행동 불가·낚시 실패를 구분하고, 길게 누를 때 클릭 녹음과 작업 녹음이 겹치지 않도록 한다. 음성 시작과 종료가 멈춰 있는 자르기·젓기 소리를 다시 키우지 않는다. 문·발걸음·동전 녹음이 있으면 합성음을 중복하지 않는다. 음악은 낮추고 작은 수확·희귀 보상 녹음은 보정했으며 단발 효과음도 TTS 중 줄인다. 원본 MP3는 변경하지 않았다. `python tools/prepare_effects_preview.py`로 약 37초의 모노 비교 음원 `output/audio/effects-preview.wav`를 만든다. FFmpeg와 Node가 필요하며 실제 동시 혼합이나 HRTF를 재현하는 파일은 아니다.

## 설정 파일

설정은 `game_config.json`에서 변경한다. 변경 후 서버를 재시작한다. 아래 값은 현재 설정 기준이다.

시간은 게임 틱, `_ms`는 밀리초, 확률은 0~1, 좌표는 도트 단위다. 엔진에서 별도로 제한하는 항목은 표 아래에 정리했다.

### 게임 규칙과 초기 상태

| 경로 | 조절 내용 / 현재 설정 |
|---|---|
| `game.start_day` | 시작 날짜: 1 |
| `resources` | 초기 골드·비료·씨앗·작물. 요리 테스트용 작물은 각 3개 |
| `time.total_cells` | 하루 활동 한도: 20 |
| `time.action_costs` | `travel`, `plant`, `water`, `fertilize`, `harvest`, `research`, `cook`, `mine`의 시간 비용 |
| `seeds.<id>.growth_days`, `yield` | 성장일, 기본 수확량 |
| `seeds.<id>.seed_price`, `crop_price` | 씨앗 구매가, 작물 판매가 |
| `seeds.<id>.seed_return_chance` | 기본 씨앗 회수 확률: 작물별 0.1 |
| `fertilizer.growth_day_bonus` | 비료 사용 시 즉시 앞당기는 성장일: 1 |
| `shop.fertilizer_price` | 비료 구매가: 12 |
| `recipes.<id>.ingredients` | 재료 ID와 필요 수량 |
| `recipes.<id>.buff_kind` | `harvest_multiplier`, `pickaxe_protection`, `time_slow` |
| `recipes.<id>.buff_multiplier`, `buff_ticks` | 음식 효과 배율과 지속시간 |
| `recipes.<id>.gesture_steps` | 단계별 `kind`, `path`, `tolerance` — 동작 종류·경로·허용 오차 |
| `research.seed_return` | `costs`, `copper_costs`, `return_chances`, `max_level` — 비용·회수 확률·최대 단계 |
| `research.field_expansion` | `initial_plot_count`, `costs`, `stone_costs` — 시작 밭 수와 추가 밭 비용 |
| `research.mineral_luck` | `costs`, `iron_costs`, `max_level`, `diamond_weight_per_level`, `double_drop_chance_per_level` |

밭 확장 비용은 골드 `[30, 50, 70, 90]`, 돌 `[5, 10, 15, 20]`이며, 시작 밭 2개와 추가 4단계로 구성된다. 씨앗 회수 연구 확률은 `[0.3, 0.6]`이다. 이 숫자는 개발 설정이며 플레이 안내에는 세부 확률을 그대로 노출하지 않는다.

### 미니게임과 입력 피드백

| 경로 | 조절 내용 / 현재 설정 |
|---|---|
| `care_minigame.target_count`, `target_positions` | 물·비료 목표 수와 후보 위치 |
| `care_minigame.tolerance` | 물·비료 목표 통과 허용 오차 |
| `care_minigame.success_ratio` | 물·비료 완료 비율: 0.65. 전부 통과하도록 바꾸려면 1.0 |
| `harvest_minigame.target_count`, `target_positions` | 수확 목표 수와 후보 위치. 완료는 전체 목표 기준 |
| `interaction.feedback.disappear_delay_ms` | 물·비료 목표와 요리 경로의 소멸 지연: 200. 1초 유지하려면 1000 |
| `interaction.feedback.visual_refresh_interval_ms` | 지연 표시 갱신 간격: 100. 엔진 최소값 50 |
| `interaction.cooking.resume_marker_delay_ms` | 진행 중단 지점 표시 대기: 400 |
| `interaction.cooking.stir_scale` | 젓기 경로 확대: 1.6. 화면 범위 내로 제한 |
| `interaction.inventory.items_per_page` | 인벤토리 페이지당 항목 수: 12, 엔진 범위 1~12 |
| `interaction.inventory.hide_zero_items` | 보유량 0인 항목 숨김: `true` |
| `interaction.sleep.blackout_ms` | 수면 중 도트 소등·입력 대기 시간: 2000 |

수확 허용 거리는 엔진에 3.5로 지정되어 있어 `harvest_minigame.tolerance`로 변경되지 않는다. F3 누름 시간은 `web/game-keys.js`의 `holdMs`에서 조정한다.

### 음량과 재생

다음 키는 모두 `interaction.audio` 아래에 있다. 음량은 0~1 범위부터 조정하고 실제 음원의 크기를 함께 확인한다.

| 키 | 조절 내용 |
|---|---|

### 배치와 이미지

`dotpad`, `time.bar`는 도트 패널 크기를, `home`, `farm`, `town`, `minimap`은 기본 배치 데이터를 관리한다. 현재 엔진은 일부 화면을 고정 격자와 영어 이름으로 정규화하므로 설정의 좌표나 `label`이 항상 그대로 표시되지는 않는다. 실제 패드 크기와 페이지 배치는 장치 규격·엔진 배치를 함께 확인해 수정한다.

시각화의 이미지 위치·크기는 `scene-objects.json`, 이미지 등록은 `visual-assets.json`, 카드 크기·색상은 `viewer.css`에서 조정한다. 이 부분은 게임 규칙 설정과 분리되어 있다.

## 향후 개발과 검증

사용자 평가에서는 게임 이해도와 재미, 촉각·음성 정보량에 따른 부담, 손 제스처의 사용성과 정확도를 확인할 예정이다.

- 손 추적 좌표 보정, 흔들림·가림 대응과 탐색/행동 입력 분리 개선
- 구형 노트북에서 입력 대기열·상태 전송·시각화 갱신 지연 측정 및 개선
- 낚시·목축·음악 활동, NPC 대화·퀘스트와 제작 시스템 확장
- 시각장애 사용자 약 6~8명을 대상으로 과제 성공률, 수행 시간, 오조작, 정보 이해, 작업 부담과 제스처 정확도 평가

사용자 평가는 아직 진행하지 않았다. 실물 패드 갱신 속도, 조명·카메라 위치·가림에 따른 추적 오차, 음성 품질을 함께 점검할 예정이다. 현재는 청각과 손 조작을 사용할 수 있는 사용자를 대상으로 한다.

## 낚시 업데이트

이동 경로는 농장 ↔ 집 ↔ 마을 ↔ 광산 ↔ 낚시 호수다. 낚싯대 없이 호수에 들어갈 수 있지만 낚시에는 낚싯대가 필요하다. 낚싯대는 100골드이며 한 개만 보유한다. 성공한 낚시 4회까지 안전하고, 5번째 성공부터 파괴 확률이 10%씩 증가한다. 꽝은 내구도 횟수에 포함하지 않는다. 파괴된 시도의 획득물은 유지되며 destroy 효과음으로 안내한다.

호수 테두리를 촉각으로 확인한 뒤, 손가락이나 마우스를 움직여 물소리를 따라간다. 소리는 포인터를 기준으로 물고기가 있는 방향에서 들리고 가까워질수록 커진다. 호수 안을 한 번 누르면 낚시하며 기본 2틱을 소비한다. 실패에도 시간이 들고, 결과가 나온 뒤 목표 위치가 바뀐다. 테두리 밖 클릭은 시간을 소비하지 않는다. 스테레오 헤드폰을 사용한다.

물고기는 Sardine, Carp, Mackerel, Bass, Catfish, Flounder, Salmon, Rainbow trout 8종이다. 획득한 물고기는 인벤토리에서 확인하고 상점에서 판매할 수 있다. 생선은 구이·스튜·튀김의 재료로 사용할 수 있다. 등급과 확률은 플레이 안내에 표시하지 않는다. 획득 시 splash를 재생하며 상급 어종이면 shine을 동시에 재생한다. 꽝에는 획득 효과음이 없다.

### 개발 설정

모든 경로는 game_config.json 기준이다. 아래 등급은 개발용 분류다.

| 항목 | 설정 |
|---|---|
| fishing.rod_price_multiplier | 곡괭이 대비 낚싯대 가격 배율, 기본 1.25 |
| fishing.near_radius / middle_radius | 도트 좌표 기준 거리, 기본 4 / 10. 나머지 호수 내부는 먼 구역 |
| fishing.zone_weights.far | 꽝/하/중/상 = 30/40/20/10 |
| fishing.zone_weights.middle | 꽝/하/중/상 = 10/30/40/20 |
| fishing.zone_weights.near | 꽝/하/중/상 = 10/20/30/40 |
| fishing.fish | 물고기 이름, 내부 등급, 판매가. 같은 등급 안에서는 동일 확률 |
| time.action_costs.fish | 낚시 시도 시간, 기본 4 |
| interaction.audio.fishing.max_gain / min_gain | 탐색음 최대/최소 음량, 기본 0.28 / 0.025 |
| interaction.audio.fishing.distance_scale | 거리별 음량 변화 범위, 기본 22도트 |
| interaction.audio.fishing.position_scale | 공간 음향 좌표 변환 비율, 기본 10 |
| interaction.audio.fishing.tts_multiplier | 음성 안내 중 탐색음 배율, 기본 0.55 |
| interaction.audio.fishing.bgm_multiplier | 낚시 중 배경음악 배율, 기본 0.2 |

기본 내부 분류: 하=Sardine/Bass/Mackerel, 중=Carp/Catfish/Flounder, 상=Salmon/Rainbow trout. 판매가는 구리 가격을 기준으로 하/중/상 그룹마다 0/3/6골드를 더한다. 현재 21/24/27골드다.

낚시 판정은 game_fishing.py에 분리했다. game_engine.py에서 입력·이동·상점·인벤토리와 연결한다. game-audio.js는 기존 water.mp3를 HRTF 공간 음향으로 반복 재생한다. 로컬 포인터 이동에서 음향을 즉시 갱신하며 API 응답을 기다리지 않는다. Visual Companion은 기존 scene3.png의 호수와 items2.png의 물고기를 사용한다. 낚싯대 이미지는 아직 없어 기존 이름 카드 대체 표시를 사용한다.

전체 파일을 기존 프로젝트에 적용하고 서버를 재시작한 뒤 Ctrl+F5로 새로고침한다. 시각화 창도 다시 연다. 저장 폴더와 가상환경은 배포 ZIP에서 제외했으며 기존 폴더를 유지한다. 기존 저장을 읽으면 낚싯대와 물고기 항목만 기본값으로 추가한다.

검증: `python -m unittest test_fishing -v`, `node test_fishing_audio.cjs`, `node test_hardware.mjs`. API 입력 검증과 자원 제공도 확인했다. 실물 패드, 헤드폰 청취, 브라우저 화면 실동작은 이번 환경에서 확인하지 못했다.

## 생선 요리와 음식 효과

주방에서 요리법을 고르고 기존 재료 선택 화면에서 채소와 보유 중인 생선 한 종류를 선택한다. 요리마다 지정된 생선만 선택할 수 있으며 선택한 생선의 등급에 따라 완성된 음식의 효과가 달라진다. 같은 효과의 음식은 한 항목으로 합쳐 보관한다. 등급명·세부 확률·배율은 게임 음성에 공개하지 않는다. 음식 안내에는 효과 이름과 남은 시간 또는 판매 횟수가 나온다.

| 음식 | 재료 | 1단계 | 2단계 | 효과 |
|---|---|---|---|---|
| Grilled fish | 생선 1 + 감자 1 | 가로 지그재그 손질 | 큰 사각형 한 바퀴 | 철·다이아몬드·상급 어종 획득 확률 증가 |
| Fish stew | 생선 1 + 토마토 1 | 가로 지그재그 손질 | 기존 젓기 | 정해진 판매 횟수 동안 판매가 증가 |
| Fried fish | 생선 1 + 당근 1 | 가로 지그재그 손질 | 기존 꽃잎 튀김 경로 | 획득량이 확률적으로 2배 |

개발 설정은 `recipes.<요리>.quality_effects`에 있다. 등급별 보관 항목은 서버 시작 시 이 설정으로 자동 생성한다. 보관 항목의 ID는 `_low`, `_medium`, `_high`로 끝나며 요리 선택 목록에는 표시하지 않는다. 기본 수치는 다음과 같다.

| 효과 | 하 / 중 / 상 재료 |
|---|---|
| 희귀 재료 | 대상 추첨 가중치 1.5 / 2 / 2.5배, 12 / 14 / 16틱 |
| 판매가 | 1.25 / 1.5 / 1.75배 (소수점 이하 버림), 판매 3 / 4 / 5회 |
| 획득량 2배 | 확률 30 / 60%, 12 / 14틱 (하 / 중만 제작 가능) |

희귀 재료 효과는 광산 연구를 적용한 뒤 철·다이아몬드 가중치를 높이며, 낚시에서는 해당 거리 구역의 상급 어종 가중치를 높인다. 최종 확률은 전체 가중치 합으로 정규화한다. 판매 효과는 화면 가격과 실제 지급액에 동일하게 적용하며, 판매 실패·구매·이동에는 횟수를 차감하지 않는다. 획득량 효과는 수확 작물·회수 씨앗·광물·물고기·완성 요리에 적용한다. 구매와 판매 골드에는 적용하지 않는다. 기존처럼 음식 효과는 한 번에 하나만 적용되며 새 음식을 먹으면 교체된다.

`game_seafood.py`는 생선 재료 선택, 음식 효과, 낚싯대·생선 가격 계산을 담당한다. 공통 조리 경로는 `cooking_methods.gestures`에서 관리하고 각 생선 요리는 `gesture_steps`의 method로 참조한다. 현재 준비 동작은 채소 썰기와 생선 손질이며, 마무리 동작은 젓기·튀김·구이다. 세 번째 준비 동작인 달걀 처리는 계획 항목으로 남겨 두었다. 기존 채소 요리의 경로는 변경하지 않았다.

낚싯대 내구도는 `fishing.rod_safe_casts`(5), `rod_break_increment`(0.1)로 조정한다. 물고기 가격은 `fish_price_base_mineral`(copper)과 `fish_price_grade_bonus`로 조정한다. 내구도와 완성 음식의 효과, 남은 판매 횟수는 저장·로드된다. 이전 저장 파일의 낚싯대는 사용 횟수 0부터 시작한다.

검증: 낚시·요리·효과 테스트 19개, 오디오 제어 테스트, 공개 상태 JSON 직렬화 검사. 실제 패드와 헤드폰 청취, 브라우저 화면 검증은 별도로 필요하다.

## 어종별 요리 제한

| 요리 | 사용 가능한 생선 (하 / 중 / 상) |
|---|---|
| 생선구이 | 고등어 / 잉어 / 연어 |
| 생선튀김 | 배스 / 가자미 / 없음 |
| 생선 스튜 | 정어리 / 메기 / 무지개송어 |

`recipes.<요리>.allowed_fish`가 재료 표시·선택·조리 시작·완료 검증에 공통으로 적용된다. `quality_effects`에서 해당 어종 등급의 효과를 조정한다. 상급 튀김은 신규 제작할 수 없다. 이전 저장에 있는 상급 튀김은 수량을 보존해 중급 튀김으로 통합하며, 사용 중인 생선 요리 효과도 새 설정으로 맞춘다. 남은 시간·판매 횟수는 새 최대치를 넘지 않는 범위에서 유지한다.

낚시는 성공·꽝 모두 2틱이다. 채광은 기존처럼 돌을 완전히 부술 때 2틱이며 개별 타격에는 차감이 없어, 돌 파괴 1회의 두 배를 기준으로 잡았다. 채광 시간은 변경하지 않았다. `time.action_costs.fish`에서 낚시 시간을 변경한다. 시간 절약 음식이 적용되면 기존 시간 감소 규칙을 따른다.

판매가 보너스는 미리보기와 실제 지급액 모두 버림 처리한다. 예: 21골드에 +25%를 적용하면 26골드다. 판매 횟수 3/4/5회와 구이 지속시간 12/14/16틱, 튀김 지속시간 12/14틱은 유지한다.

현 버전 검증: 낚시·재료 제한·효과·저장 호환 테스트 16개 및 오디오 제어 테스트 통과. 브라우저 화면·실제 기기·헤드폰 청취는 미확인.

## 낚시 음향·화면 조정

현재 설정: 낚싯대 100골드, 낚시 2틱, 성공 4회까지 안전, 5번째 성공부터 파괴 확률 10/20/30…%. 획득량 2배 보너스가 나와도 한 번의 성공으로 센다. 파괴된 시도의 획득물은 유지한다. 기존 저장에 성공 횟수가 없으면 0으로 초기화한다.

- `fishing.rod_price`: 100
- `fishing.rod_safe_catches`: 4
- `fishing.rod_break_increment`: 0.1
- `time.action_costs.fish`: 2
- `fishing.near_radius`: 4도트 (기존 중심 판정 유지)
- `fishing.middle_area_fraction`: 1/6. 중간 범위를 화면 면적의 1/6인 원으로 계산한다. 60×40에서 반경 약 11.28도트이며 그 밖은 먼 구역이다. 호수 경계에서는 영역이 잘릴 수 있다.
- `interaction.audio.fishing`: max_gain=0.85, min_gain=0.12, distance_scale=40, tts_multiplier=1, bgm_multiplier=0.2
- `interaction.audio.one_shot_gain.splash`: 0.85

낚시터의 음악은 basic 그룹이며, 물소리를 위해 기본 음악을 낮게 재생한다. 탐색 물소리는 음성 안내 중에도 줄어들지 않는다. 효과음·음소거·일시정지 설정은 기존처럼 적용된다. splash와 shine은 함께 로딩한 뒤 같은 오디오 시각에 시작한다. 등급이나 명중 범위를 음성으로 공개하지 않는다.

Visual Companion의 호수 경계선과 목표 파문 표시를 제거했다. 포인터와 획득물은 유지한다. 도트패드의 촉각 호수 외곽은 유지한다. 조리 화면에는 scene3의 주방 배경을 사용하고 기존 스튜 대체 이미지는 제거했다. 요리 선택·인벤토리 카드는 각 음식 이미지를 사용한다.

검증: Python 19개 테스트, 낚시 오디오 제어와 동시 효과음 시작 검증, JavaScript 구문 검사. 실제 화면 렌더링·실물 패드·청취 검증은 미수행.


## Fish price and effect update

물고기 판매가: 하급 24, 중급 27, 상급 36골드. 생선 요리 판매가에도 새 재료 가격이 반영됩니다. 상급 생선구이는 희귀 추첨 가중치 3배, 상급 스튜는 판매가 80% 증가(소수점 버림)입니다. 음식 이름 앞에만 소박한(Simple), 평범한(Ordinary), 호화로운(Luxurious)을 붙이며, 효과에는 접두어 없이 지속시간과 판매 횟수는 생략합니다. 실제 지속시간과 횟수는 유지됩니다. 물고기 가격은 fishing.fish_sell_prices에서 설정합니다.


요리 효과 설명은 기존 야채 요리와 동일하게 지속시간을 표시합니다. 스튜는 판매 가능 횟수를 표시하며, 사용 중에는 남은 시간 또는 횟수를 표시합니다. Simple / Ordinary / Luxurious는 음식 이름에만 붙습니다.


## Rowan과 요일별 상점 효과

Rowan은 마을의 상점 옆에 서 있습니다. 선택하면 고정 영어 Rowan 음성과 대화창이 나오며, 방향키 어느 쪽을 눌러도 마을로 돌아갑니다. F1은 미니맵, F2는 인벤토리입니다. 비주얼 컴패니언은 초상화와 대사만 표시하고 게임 입력을 보내지 않습니다.

첫 대화에서 Rowan의 수프 1개를 받습니다. 토마토 당근 스튜의 이미지와 수확 효과를 사용하며 기본 판매가는 100골드입니다. 직접 제작할 수는 없습니다. 인벤토리에서 먹거나 상점에 판 뒤 다시 대화하면 토마토·당근·감자 씨앗을 각각 1개 받습니다. 다음 대화에서 농사 안내와 채소 요청이 시작됩니다. 채소 선택 화면에서 작물 하나를 제출하면 100골드를 받습니다. 선물과 보상은 한 번만 지급되며 퀘스트 진행 상태도 저장됩니다. 기존 저장 파일은 Rowan 퀘스트를 처음부터 시작합니다.

게임 1일차는 월요일입니다. 상점의 판매·구매 다음에 있는 Calendar를 선택하면 오늘의 효과를 듣고, 각 요일을 선택해 해당 효과를 확인할 수 있습니다.

| 요일 | 효과 |
|---|---|
| 월요일 | 광석 구매가 20% 할인 |
| 화요일 | 요리 판매가 20% 증가 |
| 수요일 | 물고기 판매가 20% 증가 |
| 목요일 | 씨앗 구매가 20% 할인 |
| 금요일 | 광석 판매가 20% 증가 |
| 토요일 | 비료·곡괭이·낚싯대 구매가 20% 할인 |
| 일요일 | 전 품목 판매가 20% 증가 |

요일 효과 적용 후 소수점을 버립니다. 판매가 증가 음식 버프가 있으면 그 금액에 추가 적용하고 다시 소수점을 버립니다. 연구 비용과 퀘스트 보상은 요일 효과를 받지 않습니다.

인벤토리 첫 페이지에는 골드와 사용 가능한 음식이 표시됩니다. 나머지 재료·씨앗·작물·물고기·도구는 다음 페이지부터 표시합니다. 음식 종류가 11개를 초과하면 추가 음식 페이지를 먼저 배치해 누락을 방지합니다. 방향키는 페이지 전환만 수행하며 F2로 닫거나 F1로 미니맵을 열 수 있습니다.

`game_village.py`는 Rowan 퀘스트와 대사, 작물 제출, 요일별 가격 계산을 담당합니다. `game_config.json`의 `rowan.seed_gift_each`는 종류별 선물 씨앗 수, `rowan.vegetable_reward_gold`는 채소 제출 보상입니다. `weekly_market.discount_percent`, `bonus_percent`, `days`에서 할인·고가 매입 비율과 요일별 적용 분류를 설정합니다. 수프는 `recipes.rowan_soup`에서 설정합니다.

`web/spectator/assets/rowan.png`에 대화 초상화·전신·낚싯대를 함께 담았습니다. `visual-assets.json`에서 각 이미지 영역을, `scene-objects.json`에서 마을 배치를 관리합니다. 기존 이미지는 그대로 사용합니다. 새 에셋은 기본 이미지 생성 도구로 제작했으며, 밀짚모자·녹색 셔츠·갈색 멜빵바지를 입은 갈색 머리의 수염 있는 남성 농부와 나무 낚싯대를 투명 배경의 픽셀 아트로 구성했습니다.

검증 명령: `python -m unittest test_village -v`, `node test_hardware.mjs`. 카메라 및 실물 닷패드 검증에는 별도 tracking 모듈과 장치가 필요합니다.


## 대화·제출 화면과 도구 표시

Rowan과 대화하면 마을 페이지와 이동 버튼을 유지합니다. 채소 제출만 별도 선택 페이지로 열리며 보유 채소를 표시하고 Rowan 아이콘은 표시하지 않습니다. 채소를 선택하면 한 개를 제출하고 마을로 돌아오며, 방향키 어느 쪽으로든 취소할 수 있습니다. 상점 Calendar는 별도 화면 없이 짧은 요일별 효과 일곱 가지를 읽습니다.

초상화는 자체 6:7 비율을 사용하고, 기존 8:5 화면 비율은 메인 캔버스에만 적용합니다. 낚싯대가 있으면 낚시터에 큰 낚싯대가 표시됩니다. 곡괭이가 있으면 포인터로 지정한 광산 바위 옆에 들어 올린 곡괭이가 표시됩니다. 두 표시는 시각적 안내이며 게임 판정에는 영향을 주지 않습니다.

`assets/items3.png`는 투명 배경 3×3 스프라이트 시트입니다. 첫 행은 낚싯대·달력·새, 둘째 행은 커피콩·커피·가위, 셋째 행은 사료·식칼·벌레잡이채입니다. `visual-assets.json`에서 각 영역을 등록했습니다. 소형 낚싯대는 인벤토리와 상점에서 사용하며 기존 큰 이미지는 `fishing_rod_equipped`로 등록했습니다. 추후용 나머지 일곱 아이템은 그래픽만 추가했으며 게임 기능은 추가하지 않았습니다.

기본 이미지 생성 도구로 제작했습니다. 생성 조건은 따뜻한 색의 농장 게임용 픽셀 아트 아이템 9종, 투명 배경, 동일한 3×3 셀, 글자·프레임 없음입니다. 기존 이미지는 유지합니다.
