# 닷듀밸리 사운드와 영어 음성 목록

## 게임 이벤트와 음원

| 상황 | 음원 | 재생 방식 |
|---|---|---|
| 기본 장소 | background-basic | 배경음악 반복 |
| 농사와 요리 | background-minigame | 같은 음악 그룹 안에서는 재시작하지 않음 |
| 상점 | background-shop | 배경음악 반복 |
| 물 주기 | water | 누르는 동안 반복 |
| 비료 | soil | 누르는 동안 반복 |
| 수확 | crop | 누르는 동안 반복 |
| 자르기와 젓기 | cut, cook | 움직이는 동안 작업음 유지 |
| 목표 통과 | correct | 작업음과 독립된 성공음 |
| 이동과 입장 | step, door | 단발 효과음 |
| 거래와 유료 연구 | coin | 단발 효과음 |
| 수면 | sleep | 수면 시작 후 한 번 재생 |
| 채굴 | pickaxe, break | 타격과 파괴 효과음 |
| 희귀 획득과 도구 파괴 | shine, destroy | 해당 이벤트에 한 번 재생 |
| 낚시 획득 | splash, shine | 획득음과 희귀 효과음을 같은 시각에 시작 |
| 낚시 탐색 | water | 포인터 기준 HRTF 방향과 거리별 음량을 계속 갱신 |
| 작업 전체 완료 | complete 합성음 | 물·비료·수확·요리 완료 후 짧은 상승 음형 |
| 행동 불가 | error 합성음 | 재화 부족, 도구 없음, 잘못된 행동에 짧은 하강 음형 |
| 낚시 실패 | miss 합성음 | 획득 물소리와 구분되는 짧은 실패 음형 |
| 심기, 메뉴와 선택 | plant, page, select 합성음 | 행동 종류에 맞는 짧은 피드백 |
| 저장과 로드 완료 | complete 합성음 | 진행 저장이나 복원 성공 확인 |
| 농사·광산 미완료 목표 | HRTF 짧은 sine 방향음 | 가장 가까운 남은 목표. 가까울수록 간격이 짧고 높아짐. Target cues로 개별 조절 |

원본 녹음은 `web/audio/`의 MP3 18개다. 원본 파일은 변경하지 않았다. 짧은 안내 효과음은 `web/game-audio.js`의 `SOUND_CUES`, `feedback`, `cue`에서 관리한다. 화면 코드에 따로 있던 `playSfx` 처리는 공통 재생 모듈로 합쳤다.

## 효과음 재생과 음량 정책

- 사용자 초기 청취에서 방향감과 효과음 균형은 긍정적이었고 음성을 조금 낮추라는 의견을 받았다. 시스템과 Rowan 음성 기본 출력은 별도의 `GameSpeech` 게인으로 0.85를 사용한다. 화면의 Speech volume으로 조절하며 효과음/BGM/낚시 게인을 바꾸지 않는다. 새로고침하면 85%다.
- 작업 중의 물, 비료, 수확, 자르기와 젓기 녹음을 유지한다. 길게 누를 때 짧은 클릭 녹음과 반복 녹음이 겹치지 않게 하고, 빠르게 눌렀다 떼면 짧은 작업음이 남는다.
- 목표 한 개 통과의 `correct`와 전체 완료의 `complete`를 구분한다. 완료 시 화면 코드에서 `water`와 `fertilize`를 무조건 제외해 소리가 없던 문제를 수정했다.
- 이동의 `step`, 상점의 `door`, 거래의 `coin`이 응답에 이미 있으면 추가 합성음을 겹치지 않는다. 화면 탐색의 짧은 음은 최소 220ms 간격으로 제한한다.
- 자르기와 젓기는 움직임이 멈추면 작아진다. 음성 시작이나 종료가 멈춰 있는 작업음을 다시 키우지 않는다.
- 페이지가 바뀌면 이전 작업·목표·거래·합성 효과음과 대기 중인 디코딩을 취소한다. 채굴 타격 후 대기하던 획득 안내도 이전 광산을 떠나면 취소한다. 새 응답의 이동·입장 소리는 처리하며, 수면 녹음은 이미 시작했다면 다음 날과 일반 화면 전환에도 끝까지 유지한다. 일시정지·음소거·창 이탈은 수면을 포함해 모두 중단한다.
- 실패한 음원 요청이나 디코딩을 영구 캐시하지 않는다. 기본 1초의 `audio_retry_ms` 후 다음 행동이나 상태 갱신에서 다시 로드할 수 있다. 같은 간격 안의 반복 요청은 막고, 이미 지나간 행동의 효과음을 재생하지 않는다. 배경음도 최초 로드 실패 뒤 복구할 수 있다.
- 음악 게인은 기본 0.30, 미니게임 0.20, 상점 0.45다. 최신 팀 설정의 기본 게임 음량 0.9과 곱해 사용한다. 음성 중 음악은 추가로 0.25배, 단발 효과음과 합성음은 0.65배로 줄인다. 낚시 탐색음의 TTS 배율 1은 유지한다.
- 음원별 크기 측정에서 수확 녹음과 희귀 보상 녹음이 상대적으로 작았다. 수확 작업 게인은 1.4, 희귀 보상 `shine`은 3.0으로 보정했고 비료와 자르기 게인은 각각 0.35와 0.45로 조정했다. 이는 초기 혼합값이며 실제 사용자의 청취 결과를 바탕으로 조정한다. 숫자가 1보다 커도 원본이 작은 녹음의 선형 증폭값이며 전체 음량 슬라이더의 퍼센트와는 다르다.

`tools/prepare_effects_preview.py`는 현재 게인을 적용한 녹음과 같은 `SOUND_CUES` 정의로 약 37초의 비교 파일 `output/audio/effects-preview.wav`를 만든다. Python 환경 외에 FFmpeg와 Node가 필요하며 현재 노트북에는 준비돼 있다. 이 파일은 효과음별 모노 청취용으로 낚시 HRTF나 실제 배경음과 음성의 동시 혼합을 재현하지 않는다. 파일 생성과 소프트웨어 검사 통과를 실제 청취 품질의 최종 승인으로 취급하지 않는다.

## 음성 문장 관리

10월 18일부터 서버 음성 대기열은 오래된 브라우저 요청을 취소하고 행동/대화를 탐색과 사전 생성보다 먼저 처리한다. Rowan은 최근 실제 결과를 인사에 한 번 덧붙인다. 농사 목표 통과음과 채굴 타격음은 진행에 따라 조금 높아진다. 자세한 정책과 검증 한계는 `GAMEPLAY_UPDATE.md`에 있다.

`speech-catalog.json`은 실제 Python 코드의 고정 문장과 동적 문장 표현을 수집한 목록이다. `tools/speech_inventory.py`로 갱신한다. 변수로만 전달되는 문장과 브라우저 문장은 자동으로 펼치지 않으므로 이 파일이 모든 재생 문장을 완전히 열거하는 것은 아니다.

| 종류 | 예시 | 구현 |
|---|---|---|
| 고정 안내 | Map. Select a place. | 처음 생성한 음원을 저장하고 재사용 |
| 값이 바뀌는 안내 | Tomato seeds bought. Gold left: 24 gold | 게임이 확정한 문장을 서버에서 같은 모델로 생성 |
| 아이템 상태 | 물 필요 여부, 성장일, 보유 수량 | 게임의 기존 상태 값 사용 |
| NPC 대사 | Rowan의 인사와 농사 및 낚시 조언 | `npc_config.json`에서 인물과 상태별 대사 관리 |
| 음성 샘플 | 장소, 버튼, 수량과 낚시 안내 | `speech_config.json`의 samples |

화면에 표시할 원문과 읽을 표현은 분리한다. `F1`부터 `F4`까지는 영어 단어로 번호를 풀어 읽고, `NPC`와 `Dotdew`의 읽는 표현을 정규화한다. 실제 발음의 적절성은 샘플 청취로 확인한다.

## 첫 음성 구현 선택

첫 버전은 Piper 1.8.0과 고정 영어 모델 두 개를 사용한다. 시스템은 `en_US-hfc_female-medium`, Rowan은 `en_US-hfc_male-medium`이다. 계정과 API 사용료 없이 현재 노트북에서 음원을 만들 수 있어 초기 연결에 사용한다. 게임 화면은 OS 목소리를 선택하지 않고 서버가 생성한 WAV를 재생한다.

유료 클라우드 음성은 음질 비교가 필요할 때 추가할 수 있는 대안이다. 현재는 계정 준비 없이 실행 가능한 첫 버전에 집중하며, 실제 음색 선호는 사용자가 샘플을 듣고 결정한다.
