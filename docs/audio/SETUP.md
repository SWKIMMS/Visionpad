# 다른 PC에서 설치하고 실행하기

Python 3.11 이상과 프로젝트 소스가 필요하다. 현재 실제 확인 환경은 Mac arm64/Python 3.14.3이다. Windows용 준비·실행 파일도 만들었지만 Windows에서 직접 실행한 결과는 아직 없다.

## 처음 한 번 준비

1. 음성 작업 브랜치의 전체 소스 폴더를 준비한다. PR을 병합하기 전에는 해당 PR의 브랜치를 내려받는다. 변경 범위와 확인 순서는 `TEAM_HANDOFF.md`에 있다.
2. Python 3.11 이상을 설치한다. Windows에서는 Python 실행 파일이 PATH에 있거나 `py` 명령으로 실행돼야 한다.
3. Mac은 **setup-mac.command**, Windows는 **setup-windows.bat**를 연다. 준비 도중 표시되는 오류가 있으면 해당 안내를 해결하고 다시 실행한다.

준비 도구는 프로젝트 안의 `.venv/`를 만들거나 기존 `.venv/`, `venv/`를 사용한다. 선택한 환경에 `requirements.txt`를 설치하고 의존성, 음성 모델 다운로드와 두 목소리의 실제 WAV 생성을 확인한다. 전역 Python 환경에는 패키지를 설치하지 않는다. 설치나 합성이 실패하면 성공으로 표시하지 않고 중단한다. 깨진 기존 환경 폴더를 자동 삭제하지 않는다.

첫 패키지 설치와 음성 모델 다운로드에는 인터넷이 필요하다. 음성 서비스 계정과 API 키는 사용하지 않는다. 모델과 생성 음원은 Git에서 제외되므로 다른 PC에서도 이 준비가 필요하다. 기존 모델 파일은 다운로드 도구의 기존 파일 확인에 따라 재사용한다. 다운로드가 끊겨 손상된 파일이 남았다면 진단에 나온 `models/piper/모델명.onnx`와 같은 이름의 `.onnx.json` 파일을 다른 이름으로 옮겨 보관한 뒤 설치 준비 파일을 다시 실행한다. 다운로드 도구가 크기가 0이 아닌 손상 파일을 자동으로 다시 받는 것은 아니다.

모델과 Piper의 출처·라이선스는 `SOUND_MAP.md`를 참고한다. Node와 FFmpeg는 개발 검사와 효과음 비교 파일 생성용이며 기본 게임 실행의 필수 설치 항목은 아니다.

## 게임을 켤 때

| PC | 여는 파일 | 기본 접속 주소 |
|---|---|---|
| Mac | `start-mac.command` | `http://127.0.0.1:8000` |
| Windows | `game.bat` | `http://127.0.0.1:8003` |

Windows의 8003번 포트는 기존 설정을 유지했다. 두 실행 파일은 같은 `launch_game.py`를 사용하고 실제 주소를 음성 준비 도구에 전달한다.

실행기는 먼저 선택한 주소를 확인한다. 같은 게임이 이미 켜져 있으면 그 서버를 재사용하고 진행을 초기화하지 않는다. 다른 프로그램이 포트를 쓰고 있으면 종료시키지 않고 안내한다. 새 서버를 시작할 때는 환경을 점검하고 실제 서버 응답을 기다린 뒤 시연용 안내 203개를 준비하고 브라우저를 연다. 준비에 실패하면 위의 오류를 확인하고 재시도한다. 이미 켜져 있던 사용자 서버는 실패나 실행기 종료 때문에 종료하지 않는다.

새 서버를 시작한 실행창은 플레이하는 동안 열어 둔다. 게임에서 F3를 길게 눌러 진행을 저장한다. 서버를 닫은 뒤에는 F3 저장 목록에서 직접 불러온다. 이번 변경은 자동 로드나 게임 규칙을 추가하지 않았다.

## 문제가 있을 때

실행 환경을 활성화한 터미널에서 다음 명령으로 확인한다. Windows에서 경로를 직접 지정하려면 `.venv\Scripts\python.exe`, Mac에서는 `.venv/bin/python`을 `python` 대신 사용할 수 있다.

```bash
python tools/check_setup.py --synthesize --report output/setup-check.json
```

`OK`는 해당 항목 통과, `FIX`는 문제와 해결 방법을 뜻한다. Python과 패키지 버전, 필수 코드, 효과음 18개, 음성 모델과 설정, 저장·캐시 위치에 쓸 수 있는지 확인한다. `--synthesize`는 두 목소리로 짧은 WAV를 임시 폴더에 실제 생성한 뒤 정리한다. 실제 사용자 게임을 실행하거나 저장을 바꾸지 않는다. 이 점검만으로 실제 헤드폰과 Dot Pad가 검증된 것은 아니다.

파일·모델 존재 확인만 빠르게 하려면 `python launch_game.py --check`를 사용한다. 서버가 준비되지 않아 브라우저를 열지 못한 경우에는 실행창의 오류를 먼저 확인한다. 다른 포트로 실행하려면 다음처럼 지정한다.

```bash
python launch_game.py --port 8004 --prepare-demo
```

## 초기 설치 검증 기록 (2026-10-14)

2026년 10월 14일 현재 Mac에서 다음을 확인했다.

- 파일, 패키지, 18개 효과음과 모델 검사 통과. 임시 폴더에서 두 목소리의 실제 WAV 생성 통과. 기록은 `output/setup-check.json`이다.
- 새 실행기로 현재 8000번 서버를 재사용하고 안내 185개를 캐시에서 준비했다. 같은 Python 프로세스가 계속 실행 중이며 재시작과 게임 입력은 없었다.
- 임시 소스 복사본과 임시 포트에서 새 서버를 실제 시작하고, 새 캐시에 음성 185개를 생성했다. 1일 차의 임시 게임임을 확인하고 테스트 서버가 종료돼 포트가 닫힌 것까지 확인했다. 기록은 `output/startup-smoke.json`이며 실제 저장과 섞이지 않았다.
- 새 준비/실행 검사 15개를 포함해 Python 49개가 통과했다. 기존 Node 56개 통과 결과와 합쳐 전체 소프트웨어 검사 105개다. Mac 실행 파일 구문 검사도 통과했다.
- 설치 명령의 순서와 실패 중단, 두 운영체제의 환경 경로 선택은 자동 검사했다. 현재 사용 중인 환경에 설치 명령을 다시 실행하거나, 새 PC의 패키지 다운로드부터 전 과정을 실제로 수행한 검사는 아니다. Windows 실제 실행과 다른 PC의 음성/기기 확인은 남아 있다.

다음 작업은 다른 PC에서 이 순서로 실행하고 `setup-check.json`과 `LISTENING_CHECK.md`에 실제 결과를 남기는 것이다. 해당 PC가 준비되기 전까지는 설치·청취 검증 완료로 표시하지 않는다.

2026-10-18 통합 버전에서는 환경 점검 13개와 두 음성의 실제 합성, 203문장 사전 준비를 다시 확인했다. 최신 147개 자동 검사와 남은 검증은 `TEAM_HANDOFF.md`에 정리했다.
